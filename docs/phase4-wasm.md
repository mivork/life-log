# Phase 4 設計メモ: Rust/WASM のフロント連携

## 現状
- Rust モジュール本体は `tools/wasm-crypto/` に用意済み（検証 `validate_record_json`、暗号化 `encrypt_text` / `decrypt_text`）。
- 一時ツールチェインで `cargo test` 合格と wasm32 向けビルド成功まで確認済み。wasm-pack による JS グルー生成とフロント組み込みは未実施。再現手順は `tools/wasm-crypto/README.md` に記載。
- フロントエンド（Phase 1）は連携なしで完結している（localStorage + JSON入出力）。連携は任意の強化であり、未連携でも機能は欠けない。

## 連携時の設計
1. wasm-pack で `tools/wasm-crypto/pkg/` にビルドし、`js/wasm/` へ配置する（生成物はコミット対象にするか、ビルド手順を CI に寄せるかは連携時に決定）。
2. 記録保存前に `validate_record_json` を呼び、Go 同期ツールと同じ範囲チェックをブラウザ側でも二重化する。
3. JSON エクスポート時の任意オプションとして「パスフレーズで暗号化して書き出す」を追加する。
   - パスフレーズはメモリ上でのみ保持し、localStorage にもサーバーにも保存しない。
   - 暗号文の形式は Rust 側の仕様（base64: salt16 || nonce12 || AES-256-GCM ciphertext）に固定し、Kotlin 版とも互換を保つ。
4. インポート時は暗号文を検出したらパスフレーズ入力を求め、復号してから既存の検証・取り込みフローに渡す。

## やらないこと
- パスフレーズの保存、復旧手段の提供（忘れた場合は復号不可であることを UI で明示する）。
- 公開リポジトリへの暗号化済み実データのコミット（暗号化してあっても実データはプライベート側に置く、という合意書の原則は変えない）。
